## 关键技术判断（供后续复用）

1. **网页与小程序的界面层无法复用**——小程序无 DOM、标签体系不同、无 Teleport、样式选择器受限。
   强行复用会三端都做不好。解法是分层：令牌 100% 共享 / 逻辑 core 约 90% 共享 / 界面层各写各的，
   总工作量约 1.7 套。
2. **`@df-ui/uni` 必须源码分发**，不能预打包——小程序需要 uni-app 编译器处理 `.vue` 源码，
   走 `uni_modules` + easycom 规范。
3. **props 定义抽到独立文件**（`button.ts` 与 `button.vue` 分离），三端 import 同一份，
   从根本上防止 API 走偏。
4. **小程序 CSS 变量兼容性**需双轨：SCSS 编译期写死默认值兜底 + CSS 变量运行时覆盖换肤。
5. **色阶推导**采用 HSV 空间的 Ant Design 色板算法（色相偏移 + 饱和度/明度分段步进），
   已在预览页实现并验证。
6. **液态玻璃 = 三层叠加**：`backdrop-filter: blur + saturate`（底）× `rgba` 半透明本体（中）×
   渐变边框环 + inset 高光（顶）。缺第三层就只是磨砂塑料，不是玻璃。
7. **`backdrop-filter: url(#svgFilter)` Chrome 已验证支持**，可做真实折射位移；
   视觉增益有限、成本高，默认关闭。
8. **玻璃最大的落地风险在小程序安卓端**：部分机型不支持 backdrop-filter 或严重掉帧。
   降级方案必须在动手前定：玻璃→高不透明度纯色，但边缘高光、圆角、阴影、动效全部保留，
   保证降级后仍是同一套设计语言。
9. **玻璃只给"框架层"用**（侧边栏、导航、卡片外壳、按钮），
   表格正文与长表单一律用 `solid` 材质，否则久看伤眼。这条写进组件默认值。

## 需求收敛过程的教训（供以后复用）

用户不懂前端、也说不清想要什么时，**"猜一个做一个"效率极低**（本次连废两版）。
有效的做法是：**一次性给多个差异极大的方向并排对比，让用户用排除法收敛**。
本次 8 个方向一轮就锁定了 4 个，再一轮就定了最终方案。
