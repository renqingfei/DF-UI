# 这是什么

DF UI 是一套面向 Vue 3 的组件库，同时覆盖三个端：

| 包名 | 用在哪 | 对标 |
| --- | --- | --- |
| `@df-ui/pc` | 电脑浏览器里的后台管理系统 | Element Plus |
| `@df-ui/h5` | 手机浏览器里的网页 | Vant |
| `@df-ui/uni` | uniapp：微信小程序 / App / 多端 | uview |

## 三端为什么不是三套代码

因为界面层没法复用，但界面层之下的东西全都能复用。

小程序里没有真正的网页 DOM，标签体系也不一样（`view` 而不是 `div`），
硬要三端用同一套模板，结果是三端都做不好。所以 DF UI 是分层的：

| 层 | 复用程度 | 内容 |
| --- | --- | --- |
| 设计令牌 | **100%** | 颜色、圆角、阴影、控件尺寸、动效曲线 |
| API 契约 | **100%** | 属性名、事件名、取值枚举、默认值 |
| 界面无关逻辑 | 约 90% | 类名推导、状态判定、校验规则、日期计算 |
| 界面模板与样式 | 0% | 各端各写一份，这是刻意的 |

总工作量约 1.7 套，不是 3 套。而对使用者来说，**学一遍就能写三端**。

## API 一致性不是靠自觉

"三端 API 保持一致" 这种承诺，光靠人盯是守不住的 —— 改一处忘一处，
半年后三个包就长成三个样。所以这件事交给机器：

- 属性定义只有一份，放在 `@df-ui/core`，三端 `import` 同一个对象
- 有一个测试专门断言三端拿到的**是同一个对象**（而不是"内容看起来一样"）
- 同一组属性下，三端生成的类名必须逐字相同
- 谁想在自己端里私自重新声明一遍属性，测试立刻变红

## 移动端不是把 PC 缩小

这是最容易做错、也最影响手感的地方。DF UI 把这些写成了硬规矩：

- **控件最矮 44px**。这是成年人指尖的物理接触面积决定的，不是审美问题。
  移动端控件高度是一组独立令牌（`m-control-h-*`），测试会断言它不低于 44px，
  也不允许直接复用桌面的高度值。
- **不做悬停态**。触屏上点完，`:hover` 会黏在元素上不消失。
  H5 端的悬停样式关在 `@media (hover: hover)` 里，只对接了鼠标的设备生效。
- **触控尺寸不用 rpx**。`rpx` 会随屏幕宽度缩放，小屏手机上按钮会缩到 44pt 以下。
  装饰性间距可以用 rpx，点击区域一律用 px。
