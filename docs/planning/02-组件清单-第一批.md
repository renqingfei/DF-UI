## 一、基础与布局

### 1. Button 按钮

页面上一切"可点的动作"。

| 属性 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `type` | `default` `primary` `success` `warning` `danger` `info` | `default` | 语义色 |
| `variant` | `solid` `outline` `soft` `text` `link` | `solid` | 填充方式 |
| `size` | `small` `medium` `large` | `medium` | 尺寸 |
| `shape` | `default` `round` `circle` `square` | `default` | 形状 |
| `loading` | Boolean | `false` | 加载态，自动禁用点击并显示转圈 |
| `disabled` | Boolean | `false` | 禁用 |
| `block` | Boolean | `false` | 撑满父容器宽度 |
| `icon` | String | — | 图标名，与文字自动排布 |

事件：`click`
插槽：`default` 文字 · `icon` 自定义图标
附属：`ButtonGroup` 按钮组（相邻按钮自动合并圆角）

**平台差异**：uni 端额外支持 `open-type`（获取手机号、转发、客服等小程序原生能力），透传给底层 `button`。

---

### 2. Icon 图标

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| `name` | String | 内置图标名 |
| `size` | String / Number | 尺寸，默认继承字号 |
| `color` | String | 颜色，默认继承文字色 |
| `spin` | Boolean | 持续旋转（加载类图标用） |

**平台差异**：pc / h5 用内联 SVG（可换色、无请求）；uni 端构建期生成 base64 雪碧图与字体两套产物，规避小程序对 SVG 的支持差异。

---

### 3. Layout 布局（Row / Col）

24 栅格。

| 组件 | 属性 | 说明 |
| --- | --- | --- |
| `Row` | `gutter` `justify` `align` `wrap` | 行容器与间隔 |
| `Col` | `span` `offset` `xs` `sm` `md` `lg` `xl` | 列宽与响应式断点 |

**平台差异**：uni 端不提供 `xs~xl` 响应式断点（小程序无窗口尺寸变化场景），改为 `span` 固定分栏。

---

### 4. Space 间距

一堆元素之间自动留均匀空隙，替代手写 margin。

`direction`（horizontal/vertical）· `size`（small/medium/large/数字）· `wrap` · `align`

---

### 5. Divider 分割线

`direction` · `dashed` · `contentPosition`（left/center/right）
插槽：`default` 线中间的文字

## 二、表单

> 表单是整个组件库最花时间的部分，校验引擎放在 `@df-ui/core`，三端共用。

### 6. Form / FormItem 表单

| Form 属性 | 说明 |
| --- | --- |
| `model` | 表单数据对象 |
| `rules` | 校验规则集 |
| `labelWidth` / `labelPosition` | 标签宽度与位置（top / left / right） |
| `disabled` | 整表禁用 |
| `validateOnRuleChange` | 规则变化时是否立即校验 |
| `scrollToError` | 校验失败自动滚到第一个错误项 |

| Form 方法 | 说明 |
| --- | --- |
| `validate()` | 全表校验，返回 Promise |
| `validateField(prop)` | 校验单个字段 |
| `resetFields()` | 重置为初始值并清除校验状态 |
| `clearValidate()` | 只清除校验状态 |

| FormItem 属性 | 说明 |
| --- | --- |
| `prop` | 对应 model 中的字段路径，支持 `a.b[0].c` |
| `label` · `required` · `rules` | 标签、必填星号、单项规则 |
| `showMessage` · `error` | 错误提示显示控制与手动指定错误 |

**内置校验规则**：`required` `min` `max` `len` `pattern` `email` `mobile`（中国大陆手机号）`idCard`（含校验位）`url` `number` `integer` `range`，以及自定义同步/异步校验函数。

---

### 7. Input 输入框

`modelValue` · `type`（text/password/number/tel/idcard/digit）· `placeholder` · `clearable` · `showPassword` · `maxlength` · `showWordLimit` · `disabled` · `readonly` · `prefixIcon` · `suffixIcon` · `size` · `align`

事件：`update:modelValue` `input` `change` `focus` `blur` `clear` `keyup.enter`
插槽：`prefix` `suffix` `prepend` `append`

**平台差异**：uni 端 `prepend`/`append` 插槽受小程序 `input` 组件限制，改用外层 flex 包裹实现；`type="number"` 在 iOS 小程序上映射为 `digit`。

---

### 8. Textarea 多行输入

`autosize`（true / `{ minRows, maxRows }`）· `maxlength` · `showWordLimit` · `rows` · `resize`（PC 独有）

---

### 9. Select 选择器 / Picker

**用法一致，表现按平台习惯分化。**

| 属性 | 说明 |
| --- | --- |
| `modelValue` | 选中值 |
| `options` | `[{ label, value, disabled }]` |
| `multiple` · `multipleLimit` | 多选与上限 |
| `filterable` | 可搜索（PC 输入过滤；移动端顶部搜索框） |
| `clearable` · `disabled` · `placeholder` | — |

| 端 | 表现 |
| --- | --- |
| pc | 点击展开下拉面板，键盘上下键可选，支持分组与远程搜索 |
| h5 | 点击从底部弹出滚轮选择器，带取消/确定 |
| uni | 同 h5，滚轮基于 `picker-view` 实现 |

---

### 10. Checkbox 多选 / 11. Radio 单选

`modelValue` · `label` · `disabled` · `indeterminate`（半选，Checkbox 独有）
成组：`CheckboxGroup` / `RadioGroup`，支持 `options` 数组快速渲染、`min`/`max` 数量限制
外观：`variant`（default / button / card / tag）

---

### 12. Switch 开关

`modelValue` · `activeValue` / `inactiveValue`（支持任意值，不限布尔）· `activeText` / `inactiveText` · `loading` · `disabled` · `size`
`beforeChange`：返回 Promise，**服务端确认成功才真正切换**，期间自动显示 loading。

## 三、数据展示

### 13. Skeleton 骨架屏 ★ 重点组件

数据没回来时先显示灰色占位，避免用户盯白屏。

| 属性 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `loading` | Boolean | `true` | 为 `false` 时渲染真实内容 |
| `preset` | `text` `list` `card` `article` `table` `avatar` `image` | `text` | 预设模板，一行代码出效果 |
| `rows` | Number | `3` | 文字行数 |
| `count` | Number | `1` | 重复几组（列表场景） |
| `animated` | `shimmer` `pulse` `none` | `shimmer` | 闪光扫过 / 呼吸渐变 / 静止 |
| `round` | Boolean | `false` | 占位块用大圆角 |
| `avatar` | Boolean / `{ size, shape }` | `false` | 是否带头像占位 |
| `transition` | Boolean | `true` | 切换到真实内容时淡入淡出，不"啪"地跳变 |
| `throttle` | Number | `0` | 延迟 N 毫秒才显示骨架，避免接口很快时闪一下 |

插槽：`default` 真实内容 · `template` 完全自定义骨架结构

**自由拼装**：提供 `SkeletonItem` 子组件，`variant` 支持 `text` `circle` `rect` `image` `button`，宽高圆角随意配，能拼出任意页面形状。

```vue
<df-skeleton :loading="loading" preset="list" :count="5" avatar>
  <div v-for="item in list">…真实内容…</div>
</df-skeleton>
```

**平台差异**：uni 端动画用纯 CSS `@keyframes` + `background-position` 实现，不依赖 DOM，小程序端同样流畅。

## 四、反馈

### 21. Dialog 对话框

`modelValue` · `title` · `width` · `closeOnClickOverlay` · `showClose` · `beforeClose` · `destroyOnClose` · `lockScroll` · `center`
PC 独有：`draggable`（拖动标题栏移动）· `fullscreen` · `top`
插槽：`default` `header` `footer`
函数式调用：`DfDialog.confirm({ title, message })` 返回 Promise，`then` 表示确认、`catch` 表示取消。

**平台差异**：pc / h5 通过 Teleport 挂到 body；uni 端用固定层级 + `root-portal` 包装，规避小程序原生组件遮挡。

---

### 22. Popup 弹出层

从上下左右或中间弹出的容器，移动端的万金油。

`modelValue` · `position`（top/bottom/left/right/center）· `round` · `closeable` · `closeIcon` · `overlay` · `closeOnClickOverlay` · `safeAreaInsetBottom`（避开 iPhone 底部横条）· `zIndex`
事件：`open` `opened` `close` `closed`

---

### 23. Toast 轻提示

只用函数调用，不写标签。

```ts
DfToast.success('保存成功')
DfToast.fail('网络异常')
DfToast.loading('提交中…')   // 返回句柄，手动 close()
DfToast({ message: '自定义', duration: 3000, position: 'top' })
```

参数：`type`（success/fail/loading/text）· `message` · `duration` · `position` · `forbidClick`（期间禁止点击穿透）· `overlay`

---

### 24. Loading 加载

三种用法：
- 组件式：`<df-loading :loading="x">内容</df-loading>` 局部遮罩
- 指令式（PC / H5）：`v-loading="x"`
- 全屏式：`DfLoading.service({ fullscreen: true, text: '加载中' })`

属性：`type`（circular/spinner/dots）· `size` · `color` · `text` · `background`

---

### 25. Message 消息条

顶部滑入的通知条，可堆叠。

```ts
DfMessage.success('操作成功')
DfMessage({ type: 'warning', message: '…', duration: 3000, closable: true, grouping: true })
```

`grouping: true` 时内容相同的消息合并计数，不刷屏。

## 交付标准

每个组件视为完成，需同时满足：

1. 三端（该端应有的）实现完毕，API 与文档一致
2. 文档站有可交互 demo + 完整 props/events/slots 表格
3. 有单元测试覆盖主要交互路径（pc / h5）
4. 支持暗色主题
5. 键盘可达（PC 端）与基础无障碍属性
6. 组件级 CSS 变量可单独覆盖
