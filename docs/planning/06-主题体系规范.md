# 06 · 主题体系规范（定稿）

> 状态：**已定方向 · 待选默认主题**
> 配套预览页：`preview/df-themes.html`
> 决策：不做风格合成，四个风格**原样保留为四套内置主题**，配色不改。

---

## 一、核心决策

| 项 | 结论 |
| --- | --- |
| **默认主题** | **`clay` 黏土软糖**（用户未做任何配置时看到的样子，也是文档站默认展示） |
| 主题数量 | **4 套内置**，全部打包在组件库里 |
| 组件代码 | **只有一份**。主题 = 一份令牌配置，组件不感知主题 |
| 切换方式 | 改 `<html data-theme="xxx">`，或运行时 `DFUI.setTheme('xxx')`，无需刷新 |
| 扩展性 | 加第五套主题 = 多写一份令牌文件，**零组件改动** |
| 用户定制 | 项目方可基于任一主题覆盖若干变量，做专属配色 |

```
packages/tokens/themes/
├─ neon.ts      01 暗夜霓虹
├─ clay.ts      02 黏土软糖
├─ bento.ts     03 便当格
├─ muted.ts     04 莫兰迪柔雾
└─ index.ts     导出 + 类型定义 + 校验（保证四套 key 完全一致）
```

**硬约束**：四套主题的令牌 key 必须完全一致，CI 加校验脚本。
任何一套缺 key 都会导致该主题下某个组件"裸奔"。

## 三、跨主题必须一致的部分

主题只改**外观**，不改**结构与行为**：

| 一致 | 说明 |
| --- | --- |
| 组件 API | props / events / slots 完全相同，切主题不影响任何业务代码 |
| 布局结构 | DOM 结构一致，主题只作用于 CSS 变量 |
| 交互行为 | 点击、聚焦、键盘、无障碍语义完全一致 |
| 尺寸档位 | `small` / `medium` / `large` 三档在每套主题下都存在（具体像素值可不同） |
| 状态覆盖 | 每套主题都必须定义：默认 / 悬停 / 聚焦 / 按下 / 禁用 / 加载 / 错误 |

## 四、使用方式

```html
<!-- 静态指定 -->
<html data-theme="bento">
```

```ts
// 全局配置
app.use(DFUI, { theme: 'clay' })

// 运行时切换，无需刷新
import { setTheme } from '@df-ui/core'
setTheme('neon')

// 局部作用域：某个区块用不同主题
<div data-theme="neon"> ... </div>
```

```ts
// 基于内置主题做项目专属配色
import { defineTheme } from '@df-ui/tokens'
export default defineTheme('bento', {
  brand: '#0F62FE',
  accent: '#FF6B00',
})
```

## 五、三端适配

| 端 | 实现 |
| --- | --- |
| pc / h5 | CSS 变量，`data-theme` 挂在 `<html>`，运行时切换零成本 |
| uni（微信小程序） | 基础库 2.9.2+ 支持 CSS 变量；低版本降级：SCSS 编译期生成四套独立样式文件，按配置只打包所需主题 |
| uni（App / 其他小程序） | 同上，构建期确定主题可显著减小包体 |

**小程序包体优化**：提供构建配置 `themes: ['bento']`，只打包用到的主题，
避免四套样式全进小程序包（小程序有 2MB 主包限制）。

## 六、移动端专属尺寸规范

**教训**：初版手机端直接沿用 PC 的间距与字号，结果显得局促寒酸（用户原话："有点小气"）。
移动端必须单独定义尺寸档，不能复用桌面值。

### 尺寸对照

| 项 | PC | 移动端 | 说明 |
| --- | --- | --- | --- |
| 页面左右留白 | 18px | **18px** | 屏幕窄，留白不能再小 |
| 卡片内边距 | 17px | **18–22px** | 主视觉卡取上限 |
| 卡片间距 | 13px | **14px**，跨区块 20–22px | 用间距划分信息组 |
| 页面主标题 | 16px | **21–29px** | 移动端标题必须够大 |
| 关键数据 | 30px | **40px**（主视觉）/ 26px（次级） | 数据是移动端的视觉锚点 |
| 正文 | 14px | **14–16px** | 触屏阅读距离更近但字要更大 |
| 列表行高 | 11px 上下 | **13–15px 上下** | 触控目标 ≥ 44px |
| 底部导航 | — | 高 **68px**（含安全区 22px） | 图标 24px |
| 顶部导航 | — | 高 **52px** | 标题 16px |

### 移动端必备版式模块

光有"卡片堆叠"会显得平。以下模块是移动端撑起层次感的关键，全部纳入第一批组件：

| 模块 | 作用 | 归属组件 |
| --- | --- | --- |
| 问候栏 | 头像 + 称呼 + 一句状态 + 通知入口，页面的"人格化"开头 | `NavBar` 变体 |
| **主视觉大卡** | 主色底 + 超大数字 + 迷你图表 + 快捷按钮，一屏的视觉重心 | `Card` + `Statistic` |
| 快捷入口宫格 | 4 列图标 + 文字，把功能铺开而不是藏进菜单 | `Grid` |
| 数据三栏 | 三个数字横排，中间竖线分隔 | `Statistic` 组 |
| 状态时间轴 | 订单/流程的进度可视化 | `Steps` 移动端形态 |
| 底部固定操作栏 | 主要动作常驻底部，拇指可达 | `ActionBar` |

> 其中 `Grid` 宫格与 `ActionBar` 底部操作栏原本不在第一批清单里，
> 因为它们是移动端撑场面的关键，**追加进第一批**（第一批由 28 个增至 30 个）。
