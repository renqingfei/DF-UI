# 05 · 液态玻璃设计规范（Liquid Glass）

> 状态：**主推方案 · 待用户最终确认参数**
> 配套预览页：`preview/ios26-liquid-glass.html`
> 对标：Apple iOS 26 Liquid Glass 设计语言

---

## 一、这套风格的核心区别

传统组件库（Element / Ant Design / Vant）的控件是**贴在背景上的不透明色块**。
Liquid Glass 的控件是**一层有厚度、会透光、会折射的玻璃**，它浮在内容之上，能看见底下的东西。

| 维度 | 传统扁平 | 液态玻璃 |
| --- | --- | --- |
| 材质 | 纯色填充 | 半透明 + 背景模糊 + 饱和度提升 |
| 边缘 | 1px 灰色描边 | 渐变高光环，模拟光在玻璃边缘折射聚集 |
| 层次 | 靠阴影和边框 | 靠模糊深度、高光、真实浮起 |
| 形状 | 中小圆角 | 大圆角 / 胶囊形，控件成组浮起 |
| 颜色 | 组件自带背景色 | 颜色从背景透上来，玻璃只做"提色" |
| 动效 | 线性过渡 | 弹性曲线，按压有形变 |

---

## 二、玻璃材质的三层结构

每一片玻璃由三层叠加而成，缺一层就不像：

```
① 底层 —— backdrop-filter: blur() saturate()
   把身后的内容模糊并提高饱和度。saturate 是关键，
   没有它玻璃会发灰发脏，有了它才有"透亮"的感觉。

② 本体 —— background: rgba(玻璃色, alpha)
   浅色主题下是白色低透明度，暗色主题下是深灰。

③ 高光 —— 边缘渐变环 + 内高光 + 光标跟随高光
   inset 顶部亮线 + 底部弱反光 + 135° 渐变边框环。
   这一层决定了"像玻璃"还是"像磨砂塑料"。
```

工程实现（核心 CSS，已在预览页验证）：

```css
.lg{
  position:relative; isolation:isolate;
  border-radius: var(--df-glass-radius);
  background: rgba(var(--df-glass-rgb), var(--df-glass-alpha));
  backdrop-filter: blur(var(--df-glass-blur)) saturate(var(--df-glass-sat));
  box-shadow:
    0 10px 40px rgba(20,22,40,.16),                               /* 浮起阴影 */
    inset 0 1px 0 rgba(255,255,255,calc(.55 * var(--df-glass-edge))),  /* 顶部内高光 */
    inset 0 -1px 0 rgba(255,255,255,calc(.14 * var(--df-glass-edge))), /* 底部反光 */
    inset 0 0 22px rgba(255,255,255,calc(.10 * var(--df-glass-edge))); /* 体积感 */
}
/* 边缘高光环：用渐变 + mask 做出 1px 的折射亮边 */
.lg::before{
  content:""; position:absolute; inset:0; border-radius:inherit; padding:1px;
  background:linear-gradient(135deg,
    rgba(255,255,255,.95) 0%, rgba(255,255,255,.15) 26%,
    rgba(255,255,255,0) 48%, rgba(255,255,255,.70) 100%);
  -webkit-mask:linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite:xor; mask-composite:exclude;
  pointer-events:none;
}
```

**真实折射**（可选）：SVG `feTurbulence` + `feDisplacementMap` 作为 `backdrop-filter: url(#filter)` 使用，
Chrome 已验证支持。视觉增益有限而成本较高，**默认关闭**，作为 `refract` 属性提供。

## 三、玻璃分级（对应 iOS Materials）

不是所有地方都用同一片玻璃。按"内容需要被看多久"分级：

| 级别 | 令牌 | alpha | blur | 用在哪 |
| --- | --- | --- | --- | --- |
| ultraThin | `--df-glass-ultrathin` | .12 | 40px | 全屏遮罩、大面积背景层 |
| thin | `--df-glass-thin` | .22 | 32px | 悬浮 TabBar、导航条 |
| **regular** | `--df-glass-regular` | **.30** | **28px** | **默认**：卡片、弹层、按钮 |
| thick | `--df-glass-thick` | .55 | 24px | 侧边栏、工具栏 |
| solid | `--df-glass-solid` | .75 | 20px | **表格、表单等读写区** |

> **硬规则：数据密集区（表格正文、长表单、正文阅读）一律用 `solid` 或以上。**
> 玻璃是给"框架层"用的，不是给"内容层"用的。这条直接写进组件默认值，
> 使用者不需要自己判断。

## 四、可调令牌

预览页顶部的四个滑块，对应四个全局令牌，改一处全站生效：

| 令牌 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- |
| `--df-glass-blur` | 28px | 0–50px | 背景模糊强度。越大越"厚"，性能开销也越大 |
| `--df-glass-alpha` | .30 | .05–.92 | 玻璃本体不透明度。越小越通透 |
| `--df-glass-edge` | .80 | 0–1.5 | 边缘高光强度。0 = 无边框感，1.5 = 强烈水晶感 |
| `--df-glass-radius` | 26px | 0–42px | 圆角。iOS 观感建议 ≥ 20px |
| `--df-glass-sat` | 180% | 100–220% | 背景饱和度增强，玻璃"透亮"的关键 |
| `--df-tint` | `#0A84FF` | — | 主色，默认 iOS 系统蓝 |

**iOS 系统色板**（作为预设主色）：

| 名称 | 色值 | 名称 | 色值 |

| Purple | `#AF52DE` | Orange | `#FF9500` |

## 四点五、颜色从哪来 ★ 这套风格最容易做错的地方

**苹果桌面好看，功劳一大半在壁纸，不在控件。**

iOS 26 的玻璃控件本身是**中性无色**的：它只做三件事——把身后的内容模糊、提高饱和度、
在边缘折出一圈光。你看到的所有漂亮颜色，都是壁纸透上来的。

### 苹果的主色到底是什么

| 问题 | 答案 |
| --- | --- |
| iOS 系统强调色 | 浅色模式 `#007AFF`，深色模式 `#0A84FF`（同一个蓝的两种校准） |
| 主色用在哪 | **只用在**：开关打开态、链接、选中态、关键操作按钮、进度条 |
| 主色不用在哪 | 卡片背景、导航栏、列表底色、大面积区块——这些一律是中性玻璃 |
| 苹果自家 App | 各有各的强调色：备忘录黄、提醒橙、健康红、音乐粉红、播客紫 |
| iOS 26 新特性 | 图标可以「跟随壁纸取色」，进一步强化"颜色来自背景"这个理念 |

### 对我们的三条硬规则

1. **玻璃层不许染色。** 组件的默认背景永远是中性玻璃，不允许写 `background: 主色`。
2. **主色只做点缀。** 单屏中主色覆盖面积建议 < 8%（按钮、开关、选中态加起来）。
3. **背景层交给使用者。** 组件库提供 `<df-backdrop>` 背景组件，内置若干套流体渐变预设，
   也允许传自己的图片或渐变。**换个背景 = 换整个产品的气质**，组件一行不用改。

### 背景层规范

预览页的壁纸不是随手写的渐变，而是**湍流位移生成的流体色场**：

```
① 铺一层底色
② 叠 4–5 个高饱和大椭圆（不同色相）
③ 整组套 SVG 滤镜：feTurbulence（分形噪声）→ feDisplacementMap（位移扭曲）→ feGaussianBlur
④ 盖一层 4% 的噪点消除色带，再压一层暗角聚焦中心
```

规则圆形光斑一眼就是"程序员做的渐变"，湍流扭曲之后才有丝绸/极光那种有机感。
这套滤镜会封装进 `<df-backdrop preset="sunset|ocean|aurora|mist|graphite|emerald">`，
静态渲染一次，无运行时开销。

## 五、形状与动效

| 项 | 规范 |
| --- | --- |
| 按钮 | 胶囊形（`border-radius: height/2`），高度 44px（触控友好） |
| 卡片 | 20–26px 大圆角 |
| 分段控制器 | 外 16px / 内 13px，内嵌阴影模拟凹槽 |
| 开关 | iOS 尺寸 51×31，滑块按下时横向拉伸（液态感的关键细节） |
| 缓动曲线 | `cubic-bezier(.32,.72,0,1)` —— iOS 的标准弹性曲线 |
| 时长 | 常规 420ms，按压反馈 120ms |
| 按压反馈 | `transform: scale(.96)`，松开回弹 |
| 悬停 | 上浮 1.5px + 高光跟随光标位置 |

**连续圆角（squircle）**：iOS 用的是超椭圆而非标准圆角。
第一批用 `border-radius` 近似（差异极小），第二批考虑 `paint worklet` 或 SVG mask 实现真正的连续圆角。

## 六、三端落地与降级矩阵 ★ 最关键的一节

玻璃效果依赖 `backdrop-filter`，各平台支持度差异很大。

| 平台 | backdrop-filter | 方案 |
| --- | --- | --- |
| PC Chrome / Edge / Safari | 完整支持 | **完整玻璃** |
| PC Firefox | 支持（103+） | 完整玻璃 |
| iOS Safari H5 | 完整支持 | **完整玻璃** |
| Android Chrome H5 | 支持 | 完整玻璃，blur 上限降到 20px |
| 微信小程序 · iOS | 支持 | 完整玻璃 |
| 微信小程序 · Android | **部分机型不支持 / 明显掉帧** | **降级** |
| 支付宝 / 字节 / 百度小程序 | 支持度不一 | **降级** |
| uni-app App 端（nvue） | 不支持 | **降级** |

### 降级方案（关键：降级后不能"看起来像坏了"）

```
玻璃层  →  高不透明度纯色（alpha 提到 .82）
边缘环  →  保留（纯 CSS 渐变边框，所有平台都支持）
阴影    →  保留
圆角    →  保留
形状与布局 → 完全不变
动效    → 保留（transform / opacity 全平台支持）
```

**结果**：降级后仍然是同一套设计语言，只是"玻璃"变成了"哑光有机玻璃"，
形状、层次、动效、配色全部一致，用户不会觉得是两个产品。

### 组件 API

```vue
<!-- 自动检测平台能力，不支持则降级（默认） -->
<df-card glass="auto">…</df-card>

<!-- 强制玻璃 / 强制实心 -->
<df-card glass="always">…</df-card>
<df-card glass="never">…</df-card>

<!-- 指定材质厚度 -->
<df-card material="thin|regular|thick|solid">…</df-card>
```

全局配置：

```ts
app.use(DFUI, {
  glass: 'auto',          // auto | always | never
  glassBlur: 28,
  glassAlpha: .30,
  glassEdge: .8,
  tint: '#0A84FF',
})
```

## 七、性能约束（必须遵守）

`backdrop-filter` 会触发 GPU 合成，滥用会掉帧。硬性约束写进组件实现：

| 约束 | 数值 |
| --- | --- |
| 单屏同时存在的玻璃元素 | 建议 ≤ 8 个，超出的自动降级为 solid |
| 玻璃嵌套层数 | ≤ 2 层（玻璃套玻璃再套玻璃会糊成一片且极慢） |
| 长列表内的列表项 | **一律不用玻璃**，只有列表容器用 |
| 移动端 blur 上限 | 20px |
| 滚动中 | 提供 `blur-on-scroll="false"` 选项，滚动时临时降级保帧率 |

## 八、无障碍

| 场景 | 处理 |
| --- | --- |
| `prefers-reduced-transparency: reduce` | 自动全站降级为不透明，尊重系统设置 |
| `prefers-reduced-motion: reduce` | 关闭弹性动效与高光跟随 |
| 文字对比度 | 玻璃上的文字必须 ≥ 4.5:1；组件内置对比度检测，不达标时自动加深文字或提高玻璃厚度 |
| 深色/浅色自适应 | 玻璃跟随背景明暗自动切换亮玻璃 / 暗玻璃 |

## 九、与原四风格方案的关系

`04-设计风格与主题规范.md` 中的 A/B/C/D 四种传统风格**降级为可选预设**，
不再作为默认。它们的价值在于：

- 用户的某个项目不适合玻璃（如需要极高信息密度的报表系统）时，可一键切回
- 玻璃降级时的视觉基线来自风格 B

**默认风格 = Liquid Glass。**
